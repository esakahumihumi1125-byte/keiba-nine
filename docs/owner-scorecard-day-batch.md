# 競馬ナイン｜本人用・5項目の採点済みレースから全Rをまとめて3連単下書き化

2026-11-06。**本物のJRDB APIによる全R自動予想ではありません。** 既存の本人手入力5項目評価から、同じブラウザー内の採点済みRをまとめて計算する機能です。

## 現在使える流れ

1. 本人用Renderの `/my-scorecard` で開催日を選び、各レースの馬番と **調教／近走／適性／血統／展開** をS/A/B/Cで入力します。途中入力は `keiba-nine-owner-factor-notes-v1` に自動保存されます。
2. ④「この日に採点済みの全Rをまとめて計算」を押すと、同じ日の**保存済み**の採点済みRだけを一括計算（最大36R）。未評価の項目があるR、馬番が不正なR、取り込んだ想定メール／本人転記馬番メモとの一致が失われたRは**除外理由とともに非対象**になります。1Rもなければ何も生成しません。
3. 各Rの3連単候補、重複を除いた点数、1点100円換算額と、折り畳み式の全馬総合評価順（S=金色、A=赤系）を表示。元の既存方式：調教25／近走25／適性20／血統10／展開20、S=4/A=3/B=2/C=1。各Rの1着上位2頭、2着上位4頭、3着上位8頭、最大48点。**8頭以上では通常36点、7頭で30点、少頭数はそれより少なくなり、穴埋めしません。**
4. 「全Rを3連単下書き画面で検査（未保存）」を押して確認に同意すると、同一ブラウザータブの一時領域 `sessionStorage` に **日付・競馬場・R・1〜3着の馬番だけ**を渡し、`/my-tickets#scorebatch=v1` へ移動します。
5. 移動先では一時データを一度だけ取り出して削除し、**既存の36R一括検査と全買い目一覧**を自動的に実行。期限10分、同一日付、最大36R、合計点数、各R最大48点の整合を検査。**この時点で保存していません**。本人が確認し、最終の「確認した下書きを一括保存」を明示して初めて本人端末の下書きキーに保存します。実購入記録・結果・回収率は変更しません。

## 制限と安全設計

- 単なる**本人手入力スコアの計算とフォーメーション作成**。AIが血統、調教、当日の展開・馬場を自動評価したという意味ではありません。期待回収率、勝率、オッズによる校正、買う／見送りの最終判断も未実装。
- JRA公式の開催・確定馬番・出走取消・変更・馬場を**独立検証していません**。古い馬番、実際には開催されない場のデータも手入力があれば計算できるので、確認前に実購入してはいけません。
- 手入力した馬名、各馬の5項目ランク、JRDBの資料本文、IDや認証情報は**引き継ぎURLにも一時データにも入れません**。一時データは馬番のフォーメーションのみ、同一タブで一回のみの受け取りで、10分を超えた情報は破棄。URL fragmentは受け取り後に削除。サーバーへのデータ送信、GitHubやGoogleへの保存なし。
- 一括計算の結果は書き込み前に再検査し、源となる保存メモが変わったら引き継ぎを拒否。日付、レース、現在の入力が変わったら画面上のプレビューも無効化。端末内のスコア・馬券下書き・購入実績は混ぜません。
- `sessionStorage` に対応しないブラウザーや異なるブラウザー領域へ移動すると自動引き継ぎできません。④の4行テキストをコピーし、`/my-tickets` の「全Rの3連単下書きをまとめて貼る」に貼り付けてから検査してください。
- 最大36Rを超える記録は勝手に切り捨てずエラーで停止。3連単48点の上限、重複排除、最大300件の保存上限は既存の馬券画面でも再検査。
- JRDB β版API認証が未発行・未接続でもこの機能は使えます。ただし**レースの評価5項目は本人入力が必要**で、全Rの自動予想はまだ完成していません。

## 自動テスト

- `scripts/check-owner-factor-scorecard-ui.cjs`：保存済みの手入力評価を2R／36Rで一括化、未評価・資料不一致の除外、S/Aの全馬順位、37R超過の拒否、保存済みの採点更新による再計算停止、拒否時の無変更、URLに馬名・採点を送らないことを検証。
- `scripts/check-private-manual-tickets-ui.cjs`：同じブラウザータブからの最大36Rの一時受け取り、一回限り・期限・改ざん拒否、既存一括点数検査、事前保存なし、購入実績非変更を検証。
- この仕組みは本物の外部JRDB/JRA APIに接続しないため、テスト成功は本番の予想精度や配信の保証ではありません。
