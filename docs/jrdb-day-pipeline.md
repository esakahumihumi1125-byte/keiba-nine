# 競馬ナイン：全場・全Rの本人用データ取得準備

**状態（2026-11-05）:** 現行のRenderはログイン付きのテスト環境で、JRDBのβ版API認証情報はまだ接続していません。現時点では実際の出馬表、馬別評価、実戦3連単を自動生成しません。

## 導入済みの動線

- 本人ログイン後の `/day-pipeline` で接続設定の有無を確認できます。設定診断はJRDBへの取得要求を発しません。
- 将来、JRDB β版の**専用**認証キー・契約条件を確認して、非公開サーバーのシークレット管理に設定した場合のみ、本人がボタンを押して `GET /api/jrdb/day-pipeline?date=YYYYMMDD` を使用できます。
- 本人セッションおよび `X-Keiba-Request: private` が必要です。HTTPの通常アクセスやクロスサイト要求は拒否されます。未接続・無効な日付・GitHub Actionsは、外部への要求前に拒否します。
- 取得は対象日について `/tra`・`/tky`・`/tcy`・`/tze`・`/tka` を**それぞれ1回**。全場を対象に資料件数をまとめて照合します。登録頭数・調教・1週前・近走・提供元馬場、提供元の取消フラグ有無のみを集計し、資料の不一致を示します。
- 馬名、馬番、馬ID、元データ、認証情報、調教指数、買い目はレスポンスへ含めません。日付を指定するたびに、本人操作があって初めて実行します。サーバー保存・GitHub Pagesへの送信・Googleシートへの記録・購入は行いません。
- 資料件数が一致しても、**JRA公式との独立した出走・取消・馬場・時刻照合、実馬の10項目評価、予想精度検証は未実施**。この画面の「予想準備完了」を実戦の購入可否と同義にしてはいけません。

## β版認証後の次工程

1. JRDBから正式なβ版専用APIの発行と利用範囲を確認。通常のベーシック会員ログイン情報はAPI認証に代用しない。
2. 個人だけがアクセスできるHTTPSサーバーで、シークレット設定、取得リクエスト回数上限、データ更新時刻を検証。Render Freeプレビューに有料データを投入する前に、提供元と契約・データ管理条件を再確認。
3. 提供データの日付・レースID・馬ID/馬番の同一性、欠損、取消・変更、当日馬場を検証し、JRAの独立した許可された公式ソースによる最終確認を設計。
4. 実データの評価と3連単生成は、既存の**架空データ限定** `plan_race` を不用意に有効化せず、10項目の根拠に時刻と評価理由を紐付けてから別途実装・検証する。
5. 本人用の予想表示・購入記録とは段階的に連携。一般公開には別途、派生予想などの利用許諾が必要。

関連ソース：`scripts/jrdb_day_pipeline.py`、`scripts/jrdb_day_pipeline_ui.py`、`tests/test_jrdb_day_pipeline.py`、`tests/test_jrdb_day_pipeline_ui.py`。

JRDBの公開API仕様：https://jrdb-api.keiba.bigtime.world/docs/request-response

## 発走直前のチェック（API接続後に任意で有効化）

- `/api/jrdb/day-pipeline` の5種類の資料照合では、サーバー時刻から発走予定までの残り時間、提供元の馬場報告日時を合わせた `reviewQueue` を返します。これは **JRA公式照合を優先する順番**で、当日・発走前の出走確定や買い目の判定ではありません。時刻を過ぎたら購入対象外と明記します。
- `/day-pipeline` の本人用画面に、当日だけ使える直前資料チェックを別ボタンとして用意しました。未認証では非表示ではなく **無効** のままで、勝手に取得しません。
- JRDB公式が定義する `POST /tpd` は馬体重、馬体重増減、パドック指数、馬体コードなどを含みます。将来、β版の専用認証を受け、利用条件と保管条件を確認できた場合だけ、本人専用サーバーで `JRDB_PRIVATE_ENABLED=1` と **追加の明示 opt-in** `KEIBA_PRESTART_BODY_ENABLED=1` を設定して、認証済みの `GET /api/jrdb/prestart-body?date=YYYYMMDD` を使用できます。
- そのリクエストは **日本時間の当日のみ** 有効です。番組 `/tra`、登録馬 `/tky`、直前情報 `/tpd` をそれぞれ1回取得します。馬名・馬番・馬体重の数値・パドック指数値・オッズ・認証情報は返しません。0kg、null、身元が一致しない資料は測定値として採用しません。
- **オッズ・人気は評価しません。** `win_odds`、`place_odds`、`odds_index` は読み取り件数の評価にも使用しません。 `updated_at` もそのまま「最新の計測」と断定しません。
- 新機能は未接続のまま。現在のレンダープレビューで実データが取得できた、またはその資料から総合S/A/B/Cや実際の3連単が生成された、という意味ではありません。

実装：`scripts/jrdb_prestart_body.py`、`tests/test_jrdb_prestart_body.py`。公式仕様：https://jrdb-api.keiba.bigtime.world/docs/endpoints/today/tpd

## 調教・近走の暫定研究進捗（5種類の資料再利用）

`/api/jrdb/day-pipeline` は `/tra`、`/tky`、`/tcy`、`/tze`、`/tka` の取得結果をメモリー内で再利用して、`factorProgress` を追加で作成します。**追加のJRDB取得要求はありません。**

- 調教では `oikirisisu` と `siagarisisu` を照合した**未検証の独自閾値**により、レース別の暫定S/A/B/C/未評価件数を集計します。
- 近走では直近の走歴の着順・IDMから、別の**未検証の独自閾値**により同様の件数を計算します。新馬・走歴不足は「未評価」であり、能力Cとは判定しません。
- 同じ出走馬の2項目が両方暫定評価できた件数と、2段階以上の不一致件数をまとめます。馬番・馬名・指数・過去着順・元データ・APIシークレットは本人用HTTPレスポンスにも含めません。
- 残りの8評価項目、実戦総合S/A/B/C、予想精度、取消と馬場のJRA公式照合は**未実施**です。本人専用UIもその状態を明記し、馬券・購入記録に反映しません。
- 開催日を変更すると以前の資料・暫定評価を非表示にします。変更前の通信が後から返っても、別日の資料を再表示しない仕組みです。

関連：`scripts/jrdb_day_factor_progress.py`、`tests/test_jrdb_day_factor_progress.py`、`scripts/check-private-day-pipeline-ui.cjs`。
