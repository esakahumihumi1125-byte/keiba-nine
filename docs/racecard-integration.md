# 競馬ナイン：実データ接続時の手順と安全条件

更新：2026-11-03

## 現時点で接続済みの部分
- **racecard-engine.js**：単一レースの入力形式・馬番・取消情報・根拠付きS/A/B/Cを検査し、暫定順位と参考3連単を計算する。点数上限48点。未知の取消、根拠不足、境界同点、極端な評価横並びの場合は見送り。
- **racecard-batch.js**：最大120R、日付・競馬場・Rの重複検出、一括検証。
- **racecard-reference.js**：ユーザーが別途用意した出馬表JSONと、日付・競馬場・R、全登録馬の番号・馬名・出走取消を比較する。馬番の欠落/追加、馬名・取消の不一致を報告する。別ファイルの出典名・日時は自己申告でありJRA公式照合済みを意味しない。
- **racecard-batch.html**：iPhoneのファイルからJSONを読み込んでレース別に確認。個人端末内で動作。
- **racecard-preview-bridge.js**：一括チェックの結果を、10分以内にメイン画面の「内容を検査する」に受け渡す。また、検証用JSONをiPhoneの「ファイル」に保存できる。ファイルは既存の一括取り込み形式と互換で、UTF-8のサイズを確認する。日付・競馬場で絞って保存可能。すべて **recordType: test**、statusは draft または skip。自動保存・自動購入なし。移行先で再検査し、本人が保存を押さない限り記録しない。元の根拠メモ全文は引き継がない。
- **keiba-nine-beta51-feed-record.html**：受け渡した暫定データを既存の一括登録パネルに読み込み、正式な実戦記録・払戻には混ぜない。

## 任意の照合用JSON
`racecard-batch.html` の「別データと出馬表を照合」に、`racecard-reference.js` のJSONを貼り付けるか、端末のファイルを選択する。

```json
{
  "kind": "keiba-nine-racecard-reference",
  "schema": 1,
  "source": "出典名（入力者による記載）",
  "checkedAt": "2026-11-06T17:30:00+09:00",
  "races": [
    {
      "date": "2026-11-07",
      "track": "京都",
      "race": 1,
      "complete": true,
      "horses": [
        {"number": 1, "name": "架空の書式例", "scratched": false}
      ]
    }
  ]
}
```

これは構造例で実在出馬表ではない。比較するすべてのレースの全頭データを用意する。照合元が指定されれば、不一致や形式エラーがある間は検証用のプレビュー保存・メイン画面への転送を止める。照合用JSONを指定しない場合は従来どおり、未照合かつ実戦利用不可の`test`データのみ出力する。**提供元の真正性・利用権限・JRA公式との一致・最新情報を検証したものではない。**

## 未接続の部分（完成済みと表示しない）
1. JRA/JRDBなどからの出馬表・取消・発走時刻・直近成績・調教データの取得。
2. 提供元データの利用権限・利用目的（個人用／一般公開）についての契約確認。
3. 取得データを独立に評価S/A/B/Cへ変換する実予想ロジック。現状は **与えられた評価を加重集計するだけ**。
4. JRA公式出馬表との馬名・馬番・取消・開催日・発走時刻・馬場の照合。
5. 利用権限に応じたプライベート同期。GitHub Pages公開JSONへ契約データを流すことはしない。
6. 実際の成績・払戻取得と、ユーザーの実購入記録の突合。推定収支と実収支を混ぜない。

## 追加する際の入力契約
受け入れは、提供元・契約範囲・取得日時・開催日・競馬場・R・馬番・馬名・取消、出典付き近走/調教/適性/血統/展開を備える段階的なアダプターとする。提供元個別の形式は、その仕様書と利用権限を確認してから別モジュールで変換する。

一括JSON（現段階）のルート形式：

```json
{
  "kind": "keiba-nine-racecards",
  "schema": 1,
  "source": "許諾済み提供元",
  "licenseConfirmed": true,
  "racecards": [
    {"date": "YYYY-MM-DD", "track": "京都", "race": 1, "horses": []}
  ]
}
```

これは形状のみの説明。horsesは1〜18頭が必須で、各馬に number/name/scratched、および必要な場合は evidence grade/note が必要。利用許諾フラグは本人申告であり、契約上の権利を証明しない。

## 必須の公開防止ルール
- 提供元のデータ・認証情報・APIキー・非公開出馬表JSONを GitHub 公開リポジトリや GitHub Pages にコミットしない。
- 予想ロジックの計算結果であっても、契約上の二次利用/公開制限を確認する。
- データ不足・開催なし・日付不一致・取消未確認では、捏造予想や架空馬名を公開しない。
- 検証用 draft/test のままで実戦の購入支援に転送しない。正式な actual 記録は本人の購入申告に限る。
- 現在のアプリはMy Keiba投票・即PATの実購入APIを利用していない。投票を行ったと表示しない。
