# 本人用の接続確認サービス（未設置）

`scripts/private_service.py` に標準ライブラリだけで動くWSGIアプリを用意しました。
現在のGitHub Pagesとは別のサーバーが必要です。まだ専用URL、HTTPS証明書、
本番認証情報、JRDBの接続情報は設定していません。

## 用意した機能

- `/`：本人用の接続確認画面。開催日を選んでレース情報を取得する。
- `/api/status`：接続設定があるかだけ返す。認証キーは返さない。
- `/api/jrdb/program?date=YYYYMMDD`：本人認証後だけ、固定のJRDBクライアントを呼ぶ。
- `/api/research`：架空データの10項目評価と最大40点の組み立てを確認する。
  実データの予想生成には未対応。

公開アプリ、Googleシート、ファイルへの自動書き込みは行いません。
実データの評価・予想表示と非公開の保存先は次の別工程です。

## 認証と通信

全ページ・全APIにHTTP Basicの本人認証が必要です。ユーザー名は既定で `owner`。
パスワードはサーバーのシークレット管理機能に登録するランダム生成値を使います。
GitHubやJRDBのログインパスワードを流用せず、公開コードやチャットへ貼りません。
ブラウザーは認証ダイアログを表示します。

`KEIBA_OWNER_PASSWORD` は32文字以上かつ12種類以上の文字が必要。
この最低条件だけでランダム性を保証するわけではありません。シークレット生成機能を
使って生成してください。未設定ならサービスは起動しません。

本番はHTTPS必須で、`wsgi.url_scheme` が `https` でない要求を拒否します。
アプリ自体は `X-Forwarded-Proto` を信用しません。TLSを終端するサーバー側で
信頼するプロキシを限定し、正しいschemeを渡す必要があります。
バックエンドの直接ポートをインターネットへ露出させないでください。

APIには専用ヘッダーが必要です。クロスサイト要求は拒否し、CORS許可を出しません。
レスポンスはno-store、埋め込み禁止。リポジトリの任意ファイルは配信しません。
ホスティング側でも要求本文・認証ヘッダー・応答データをログへ記録しない設定が必要です。
Basic認証はブラウザーが資格情報を保持するため、この版には独立したセッション失効・
ログアウト機能はありません。本番の本人ログイン方式は設置先に合わせて最終確認します。

## 本番設置前に必要な項目

1. HTTPS対応のPython WSGI設置先と、本人だけが管理できるシークレット設定。
2. `KEIBA_OWNER_PASSWORD`、必要なら `KEIBA_OWNER_USERNAME`。
3. AIコース契約後の `JRDB_API_KEY`, `JRDB_AUTH_KEY`。
4. 個人利用の非公開構成を確認後に `JRDB_PRIVATE_ENABLED=1`。
5. 認証なし・誤った資格情報・直接URL・HTTP接続でデータが取得できないことを実機確認。
6. 正しい本人認証でのみ接続できることを確認し、実データの形式を検証。

GitHub Actions内ではJRDB取得を有効にできません。
この認証はJRDBの会員向けアプリ連携APIではなく、本人だけの接続確認用です。
一般ユーザーへの販売・共有は実装していません。

## ローカル開発とテスト

本番設置ではないローカル試験に限り、`KEIBA_ALLOW_LOCAL_HTTP=1` を設定できます。
この例外は接続元が127.0.0.1または::1の場合のみ。標準の起動コードも
127.0.0.1:8765にしかバインドしません。本番の公開サーバーとしては使いません。

```sh
python -m unittest discover -s tests -p 'test_*.py'
```

53件のテストで、研究機能・JRDBクライアント・本人認証付きのリクエスト処理を確認。
JRDBの実サービスへの接続や、本番TLS・iPhone実機での認証は未確認です。
