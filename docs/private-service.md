# 本人用の接続確認サービス（架空データ用プレビューのみ設置済み）

`scripts/private_service.py` に標準ライブラリだけで動くWSGIアプリを用意しました。
既存のGitHub Pagesとは別に、Render Freeの架空データ専用プレビューを設置し、
本人のiPhoneからHTTPS・本人認証と架空8頭の分析動作を確認しました。
ただし**有料JRDBの実データを扱う本番用の非公開サーバーは未設置**で、
実データ接続や公式予想の自動生成はまだ有効ではありません。

## 用意した機能

- `/`：本人用の接続確認画面。開催日を選んでレース情報を取得する。
- `/api/status`：接続設定があるかだけ返す。認証キーは返さない。
- `/api/jrdb/program?date=YYYYMMDD` で取得した番組から、iPhoneで
  開催日 → 競馬場 → 1R～12Rを**選択するだけ**で指定できます。
  取得した開催日に存在するレースだけを候補に表示し、日付変更で以前の選択は消去。
  レース名の手入力は不要ですが、JRDB認証と非公開実行環境が必須です。
  **現在のRender Freeの架空プレビューでは無効**で、
  ただし「架空レースで選択操作を試す」を押すと、ネットワークへ接続せず、
  **2099年1月1日・架空3レース**による選択UIだけを動かせます。
  開催日変更時に架空の候補は消え、実在のレースと混同しない表示です。
  実際の出走馬名、JRA公式取消、10項目の総合評価や3連単は生成しません。
- 番組取得後に競馬場・レースを選択すると、本人用の
  **「選んだ1Rの資料をまとめて確認」** を利用できます。
  本人が押したときだけ、**1つの認証付きAPI**
  `GET /api/jrdb/selected-readiness?date=YYYYMMDD&track=京都&race=1`
  を1回呼びます。本人専用サーバー内で /tra・/tky・/tcy・/tze・/tka
  を各1回読み、同じリクエスト内で資料件数と当日の状態を照合します。
  旧方式のような画面からの資料API・当日情報APIの二重取得はしません。
  JRA公式の独立取得はまだ未接続です。
  出走馬件数、調教・1週前・近走の不足数、公式の取消・馬場・時刻の
  未照合状態をまとめて表示し、総合評価や3連単が作成できたとは表示しません。
  調教と近走については、別々に算出した仮のS/A/B/Cを内部メモリ上で突き合わせ、
  **両方評価あり・片方のみ・両方未評価、評価差が2段階以上**の頭数を追加表示します。
  これは本人用の件数チェックのみ。馬名・馬番・個別指数を応答せず、
  **残り8項目・当日適性・公式取消を評価していない**ため、総合S/A/B/Cや
  1着候補を自動確定するものではありません。実際の勝率・回収率との
  検証もまだありません。
  **展開・脚質の材料**として、同じ近走データに記録された過去最大3走の
  4コーナー位置も読み、2走以上の観測に限って「前方・後方・混在」の頭数を集計します。
  位置取りはコース・距離や相手に左右されるため、**脚質の断定やペース予想はしません**。
  `scripts/jrdb_private_factor_bridge.py` は内部で馬別の10項目スロットを準備しますが、
  調教・近走のランクは未検証の仮説、展開・脚質は観測のみ（評価は未評価）、
  初期スロットの残り7項目は未接続でした。外部に返すのは指定された1Rの件数だけです。
  **選択した1Rの資料確認**には、さらに
  `scripts/jrdb_entry_rotation_materials.py` を接続しました。
  JRDB公式の `/tky` 項目 `bracket_number`・`weight_to_carry`・
  `sire_name`・`mare_sire_name` と、`/tze` の前走日付から
  枠・斤量・父/母父の記録有無、前走間隔（14日未満、14〜55日、
  56日以上、不明）を内部の未評価スロットに整理します。
  **新たな有料取得はせず**、選択1Rの集計のみを表示します。
  これで選択1Rの内部表は調教・近走の未検証仮ランク2項目、
  過去4角位置＋血統＋枠斤量＋ローテの観測4項目に加え、
  `/tky` の `jockey_name`・`jockey_cd`・`trainer_name`・`trainer_cd` と
  `bodytype`・`horse_bodytype_integration_cd1`〜`cd3` から
  騎手・厩舎の登録有無と馬体形状コード有無の**観測2項目**も接続します。
  騎手・調教師の実績や、馬体の状態・適性は**未評価**です。
  当日の馬体重・増減は別の `/tpd` に属し、この連携では**取得しません**。
  したがって本人用選択レースの内部表は観測込み8項目・未接続2項目
  （コース距離・馬場）となります。別途の履歴照合はこの画面の一括確認では行いません。
  馬名・騎手名・厩舎名・馬体コードの個別値はブラウザーへ返しません。
  コース距離・馬場は別途、明示的な過去履歴照合による観測が可能です。
  馬名・父馬名・母父馬名・枠番・斤量・前走日付など**個別情報は返しません**。
  記録の存在は適性・斤量有利・休養明けの好走・馬券候補を保証しません。
  **騎手・厩舎・馬体の記録有無を追加しても、全10項目の総合S/A/B/Cと3連単の自動生成は未完成です。**
  履歴照合を**本人が明示的に実行した場合に限り**、追加の
  `scripts/jrdb_course_ground_factor_bridge.py` が同じ過去番組・馬場の
  取得済み資料を出走馬番号に内部結合します。追加取得は行いません。
  `course_distance` と `ground` の2項目は、コース/芝ダートと
  距離前後200m以内の履歴走数、当日の馬場が分かっている場合の
  過去馬場一致件数、重・不良の比較履歴件数と未照合走数をそれぞれ
  **未評価の観測資料**として接続します。未取得の馬場や過去走を
  不適性とみなさず、1頭の履歴があっても予想・買い目を作りません。
  `/api/jrdb/history` の戻り値は `privateHistoryFactors` の
  **1Rごとの集計のみ**。馬番・馬名・有料の個別履歴・レースキーは
  ブラウザーへ返しません。未接続5項目に加え、展開・距離・馬場は
  観測のみなので、**調教・近走以外の8項目はまだ評価できません**。
  実データ接続・ライセンス確認・JRA公式照合・総合評価・
  3連単の自動生成は依然として未完成です。

  **架空2099年テスト中は無効**。日付・場・レース変更時には前の
  確認結果を消し、取得途中に選択が変わっても古い結果を表示しません。
  この画面はブラウザーへ有料の馬別情報を返さず、許諾された非公開
  接続が有効になるまでは使用できません。
  **本人認証・追加ヘッダー・正しい日付／競馬場／Rを要求**し、
  未接続・間違った入力・未登録レース・複数候補・内部状態の不一致は
  通知して停止します。応答は指定された1Rの集計だけで、馬名・馬番・
  有料の個別記録・APIキーを返さず、利用者の記録を更新しません。
- `/api/setup`：本人認証後に、HTTPS/開発用ループバック、JRDBの接続設定有無、未接続の機能と次の準備項目を返す。API通信テストは実行せず、認証キーも返さない。
- `/` の「安全な設定診断を実行」で、iPhoneから上記の状態を表示する。
- `/api/jrdb/program?date=YYYYMMDD`：本人認証後だけ、固定のJRDBクライアントを呼ぶ。
- `/api/research`：架空データの10項目評価と最大40点の組み立てを確認する。
  実データの予想生成には未対応。
- 本人専用画面の「架空8頭で動作確認」で、根拠付き10項目の架空評価→S/A/B/C総合ランク→3連単参考組み合わせを1回の操作で確認できる。
- 別の架空JSONの読み込みにも対応。実データやJRDBの原データは入れない。
  `/api/research` は `recordType: test` に加えて根拠 `sourceId: synthetic` のみ受付け、実データを検証用と偽った入力は拒否する。
- 表示・計算のみで、Googleシート・正式予想・購入記録・GitHub Pagesを更新しない。

公開アプリ、Googleシート、ファイルへの自動書き込みは行いません。
実データの評価・予想表示と非公開の保存先は次の別工程です。

## 認証と通信

全ページ・全APIにHTTP Basicの本人認証が必要です。ユーザー名は既定で `owner`。
パスワードはサーバーのシークレット管理機能に登録するランダム生成値を使います。
GitHubやJRDBのログインパスワードを流用せず、公開コードやチャットへ貼りません。
ブラウザーは認証ダイアログを表示します。

`KEIBA_OWNER_PASSWORD` は32文字以上かつ12種類以上の文字が必要。
この最低条件だけでランダム性を保証するわけではありません。シークレット生成機能を
使って生成してください。未設定ならサービスは起動しません。

本番はHTTPS必須で、`wsgi.url_scheme` が `https` でない要求を拒否します。
アプリ自体は `X-Forwarded-Proto` を信用しません。TLSを終端するサーバー側で
信頼するプロキシを限定し、正しいschemeを渡す必要があります。
バックエンドの直接ポートをインターネットへ露出させないでください。

APIには専用ヘッダーが必要です。クロスサイト要求は拒否し、CORS許可を出しません。
レスポンスはno-store、埋め込み禁止。リポジトリの任意ファイルは配信しません。
ホスティング側でも要求本文・認証ヘッダー・応答データをログへ記録しない設定が必要です。
Basic認証はブラウザーが資格情報を保持するため、この版には独立したセッション失効・
ログアウト機能はありません。本番の本人ログイン方式は設置先に合わせて最終確認します。

## 本番設置前に必要な項目

1. HTTPS対応のPython WSGI設置先と、本人だけが管理できるシークレット設定。
2. `KEIBA_OWNER_PASSWORD`、必要なら `KEIBA_OWNER_USERNAME`。
3. JRDBからβ版用の**専用API認証情報**が発行され、利用範囲が確認できた場合のみ `JRDB_API_KEY`, `JRDB_AUTH_KEY` を本人用サーバーのシークレット機能に設定する。β版の利用条件はベーシックコースでのテストと案内されているが、正式版のAIコース条件とは別。会員パスワードの代用は禁止。
4. 個人利用の非公開構成を確認後に `JRDB_PRIVATE_ENABLED=1`。
5. 認証なし・誤った資格情報・直接URL・HTTP接続でデータが取得できないことを実機確認。
6. 正しい本人認証でのみ接続できることを確認し、実データの形式を検証。

GitHub Actions内ではJRDB取得を有効にできません。
この認証はJRDBの会員向けアプリ連携APIではなく、本人だけの接続確認用です。
一般ユーザーへの販売・共有は実装していません。

## ローカル開発とテスト

本番設置ではないローカル試験に限り、`KEIBA_ALLOW_LOCAL_HTTP=1` を設定できます。
この例外は接続元が127.0.0.1または::1の場合のみ。標準の起動コードも
127.0.0.1:8765にしかバインドしません。本番の公開サーバーとしては使いません。
`KEIBA_ALLOW_LOCAL_HTTP=1` と `JRDB_PRIVATE_ENABLED=1` を同時に指定したサーバーは安全のため起動を拒否します。

```sh
python -m unittest discover -s tests -p 'test_*.py'
```

GitHub Actionsの `Private service checks` で、研究機能・JRDBクライアント・本人認証付きのリクエスト処理・設定診断をモックデータで検証します。
JRDBの実サービスへの接続や、本番TLS・iPhone実機での認証は未確認です。

## 初回の設定診断で確認すること

- 画面の「安全な設定診断を実行」を押すと、本人認証済み・通信方式・JRDB接続設定の有無を確認できる。
- `JRDB接続設定あり` はキーの有無だけの判定。**API接続成功・データ取得・予想生成の成功ではない**。
- β版APIの実際の発行・取得・デプロイ前は、本人用の非公開サーバーを設置したと表明しない。
- 既存のGitHub Pagesは静的な公開サイトであり、この診断画面をホストできない。安全な本人専用サーバーを利用するか、CodespacesのPrivateポートで架空データの設定診断を行う。
