# 本人用・3連単下書き／実戦購入記録（v8）

## 使い方

本人認証済みの Render プレビューの最上部にある
**「自分の3連単を作る（手動）」** から、`/my-tickets` を開きます。

1. 開催日（実際の日付も選べる）、競馬場、1R〜12Rを選択。
2. **1着・2着・3着の馬番**をタップしてフォーメーションを作成。
3. 同一馬を複数着順に割り当てた重複・あり得ない組合せは除外。
4. **1点100円で実点数と金額を表示、48点超は保存不可。**
5. 「このレースの下書きを保存」を押すと、本人の**現在のブラウザー内**に保存。
6. 保存した日付ごとに一覧表示。同じレースを編集・上書き・削除でき、
   JSONファイルにバックアップを書き出せます。

例：1着①②、2着①②③④、3着①〜⑧では
購入可能な異なる3頭の順列が **36点／3,600円** になります。

## 大事な制限

- この機能は**本人が選んだ未購入の下書き**で、
  **競馬ナインAIの実馬S/A/B/C評価・買い目推薦ではありません**。
  JRAの当日出走表や取消、馬場、結果、競馬エイト、JRDBなどの
  公式・有料データへのアクセスも行いません。
- 同じ画面の「購入した馬券と回収率」で、**実際に買ったと本人が確認した**3連単を
  1点あたり100円単位で購入記録に追加できます。購入直後の払戻は
  **未確定**にして、あとから外れ0円や実際の払戻額を入力・修正できます。
  確定した購入分だけを対象に、投資・払戻・回収率・収支を計算します。
  未確定分は金額・件数を別表示し、回収率に混ぜません。
- 投票ボタン、My KEIBA・即PAT、**JRAでの購入事実や払戻の自動確認**、
  Googleシートへの記録やGoogle同期は**未接続**。
  既存の公開側 `personal-record.html` とは自動集計しません。
- 保存先は同じブラウザーの `localStorage` のみで、サーバーへの送信はなし。
  ChatGPT内ブラウザーとSafariの保存領域が分かれる場合があります。
  プライベートブラウズ、閲覧データ削除、端末変更、再インストールでは
  記録が失われることがあるため、SafariからJSONバックアップを推奨。
  下書き・実戦購入記録はそれぞれ **JSONの書き出しと復元** に対応。復元は本人が選んだバックアップファイルをブラウザー内で解析し、種類・上限・重複・点数・購入額を検証したあと、確認ダイアログを経て **現在の同種記録を全件置き換える**。混ぜ合わせ・自動マージは行わない。復元前に必ず現在の記録をJSONでバックアップ。1ファイル上限1MB、下書き300件・購入500件まで。自動同期・サーバー保存は未対応。
- 最大300レースの手動下書き。既存レースを上書きする際と削除する際は
  操作確認。保存失敗時には成功表示をしません。
- 本人専用 Basic または署名Cookie認証と同一 HTTPS サービス内だけで
  HTML・JS・CSSを提供します。未認証アクセスはログイン画面へ案内し、
  有料データや予想履歴を含むレスポンスは返しません。
- Render の Free はスリープします。GitHub自動テスト成功後の
  デプロイ設定をユーザーが有効にしていますが、
  GitHub統合だけで実際の Render 配信済みとは断定できません。

## 次の段階

バックアップ復元後の重複防止と、安全な端末間移行の使いやすさを改善する。
券種や購入時刻、購入済み馬券の訂正手順を改善し、
許諾・データ品質の確認を満たす出馬表と評価根拠の接続を検討する。
現時点では手動の収支記録とAI予想を完全に分離する。

## 2026-11-05：JSON復元（本人用）

1. 以前の端末やブラウザーで `下書きをJSONでバックアップ` と `実戦購入記録をJSONでバックアップ` を別々に保存する。
2. 新しい環境の `/my-tickets` で、対応する「JSONバックアップから復元」からファイルを選ぶ。
3. ファイル内容を検証し、同種の現在の記録をすべて置き換える確認ダイアログに同意すると復元。下書きと実戦記録は混ざらない。
4. 復元後に日付を選び直し、下書きの点数と購入記録の払戻・回収率を確認する。

**注意：** バックアップファイルを紛失すると他端末では復元できません。ファイルはSafari内で読み込み、Render・Google・GitHubへ送信されません。復元はJRAの購入証明や実馬AI予想を意味しません。既存記録を残して追記する機能ではありません。

## 2026-11-05：ChatGPTのフォーメーションを3行で貼り付け

本人用 `/my-tickets` で日付・競馬場・レースを選び、
**「ChatGPTの3連単をまとめて貼る」**を開く。
次のように1着・2着・3着を**それぞれ1行**で貼り付ける。

```text
1着：①②
2着：①②③④
3着：①②③④⑤⑥⑦⑧
```

「貼り付けた3連単を反映」を押すと、重複組み合わせを除いた36点／3,600円を**編集中のフォームだけ**に反映する。半角数字・全角数字・①〜⑱、カンマ・読点・中点・空白区切りにも対応。

- 日付／競馬場／Rが未指定、3行以外、馬番の重複や不正、点数0または49点以上は反映しない。複数馬を同じ着順に重複記載することも禁止。
- 貼付前に編集中の選択があれば置換の確認を出す。拒否・エラーなら編集中の馬番を変更しない。
- **貼り付けても自動保存しない。購入済みの記録にも変換しない。** 48点以内であること、正しい実レースの日付・出走馬・取消を本人が確認してから保存する。
- 保存済みの下書き／実購入記録を自動変更せず、いずれもブラウザーだけで処理。通信も有料データ取得もしない。

`scripts/check-private-manual-tickets-ui.cjs` のテストで
丸数字が連続している形式、全角数字、48点超過、不正な文字、
未選択日付と既存保存を保護する動作を検証する。

## 2026-11-05：最大36Rの3連単を一括で下書き登録

本人用 `/my-tickets` の「全Rの3連単下書きをまとめて貼る」を開いて、次の形式をコピーする（すべて**例示用**の仮馬番。実レースの出馬表ではありません）。

```text
2026-11-07 東京1R
1着：①②
2着：①②③④
3着：①②③④⑤⑥⑦⑧

2026-11-07 京都1R
1着：①
2着：②③
3着：②③④
```

- 「全レースの点数を検査する」では**一切保存しない**。最大36Rで、各レースは日付・競馬場・Rの見出しと1着・2着・3着の計4行。日付の重複・同一開催の重複・0点・49点以上・不正な馬番・フォーマット違反があれば全体を停止する。
- 確認一覧に各レースの点数・100円換算額・新規/上書きを表示する。本人が「確認した下書きを一括保存」を押して確認ダイアログに同意した場合のみ、既存の手動下書き保存キー `keiba-nine-owner-ticket-drafts-v1` へ**一度だけ**上書き/追記する。300レース上限・復元データ検証を維持する。保存に失敗したら元のデータを保持する。
- 開催日を選択すると、その日の下書きレース数・総点数・100円換算の合計額を表示する。**実際の購入金額ではない**。出走馬の自動公式照合、JRDB自動連携、S/A/B/C実予想、購入、払戻、Google同期は実施しない。
- レース出走確定・取消、開催場、馬番、馬場を自分で公式に確認してから実戦利用する。取り込む内容はChatGPT等の下書きを**本人がコピーしたもの**として扱い、出典検証済みとは表示しない。
- 保存処理・確認は本人ブラウザーのJavaScriptのみで完結し、まとめ貼り付けた原文やJRDB会員データをサーバー・公開GitHub・Googleシートへ送信しない。

実装：`scripts/manual_ticket_book.py`。テスト：`scripts/check-private-manual-tickets-ui.cjs`。GitHub Actions `Private service checks` の結果も確認する。

## 2026-11-05：全Rの保存前レビューと個別修正

- 一括貼り付けの「全レースの点数を検査する」の結果は、日付・競馬場・R別の折りたたみ表示。開くと**1着／2着／3着の候補**と、重複・同一馬の複数着順を排除した**実際の全3連単買い目（最大48点／R）**を確認できる。
- 一括プレビューの内容は検査時点の仮の買い目で、JRA公式の出走馬・取消・発走時刻を自動検証したものではない。保存には依然として本人の明示的な確認が必要。
- 保存済み下書き一覧の「編集」は、対象レースを選択して画面上部のフォーメーション入力欄へ移動する。**編集を開いただけでは保存や購入を行わない**。変更後も別途保存ボタンを押す。

## 2026-11-05：ホーム画面版の最新版検知と編集中保護

- 本人用トップ `/` と `/preview-v2`、本人用3連単 `/my-tickets` に、そのRender応答の版識別子を埋め込む。版は `UI_VERSION` と、Renderが報告するコミット先頭12桁（無い場合 `not-reported`）を使用。シークレットや会員データを識別子に含めない。
- 本人のページが表示されたとき、または非表示から復帰したときだけ、認証付き・`no-store` で既存の `GET /ui-version` と照合する。**バックグラウンド定期通信はしない**。サーバーの更新が確認でき、トップが未操作の場合だけトップを自動で読み込み直す。

- `RENDER_GIT_COMMIT` が報告されない環境では、`UI_VERSION` を更新していなければ**表示済み画面から新旧を自動判定できない場合がある**。通常の新規ページ遷移では従来の`Cache-Control: no-store`が有効で、新しいコードを読む。GitHub Actions成功だけではRenderの本番配信済み、iPhone実機の更新動作を保証しない。
