# 本人用・3連単下書き／実戦購入記録（v8）

## 使い方

本人認証済みの Render プレビューの最上部にある
**「自分の3連単を作る（手動）」** から、`/my-tickets` を開きます。

1. 開催日（実際の日付も選べる）、競馬場、1R〜12Rを選択。
2. **1着・2着・3着の馬番**をタップしてフォーメーションを作成。
3. 同一馬を複数着順に割り当てた重複・あり得ない組合せは除外。
4. **1点100円で実点数と金額を表示、48点超は保存不可。**
5. 「このレースの下書きを保存」を押すと、本人の**現在のブラウザー内**に保存。
6. 保存した日付ごとに一覧表示。同じレースを編集・上書き・削除でき、
   JSONファイルにバックアップを書き出せます。

例：1着①②、2着①②③④、3着①〜⑧では
購入可能な異なる3頭の順列が **36点／3,600円** になります。

## 大事な制限

- この機能は**本人が選んだ未購入の下書き**で、
  **競馬ナインAIの実馬S/A/B/C評価・買い目推薦ではありません**。
  JRAの当日出走表や取消、馬場、結果、競馬エイト、JRDBなどの
  公式・有料データへのアクセスも行いません。
- 同じ画面の「購入した馬券と回収率」で、**実際に買ったと本人が確認した**3連単を
  1点あたり100円単位で購入記録に追加できます。購入直後の払戻は
  **未確定**にして、あとから外れ0円や実際の払戻額を入力・修正できます。
  確定した購入分だけを対象に、投資・払戻・回収率・収支を計算します。
  未確定分は金額・件数を別表示し、回収率に混ぜません。
- 投票ボタン、My KEIBA・即PAT、**JRAでの購入事実や払戻の自動確認**、
  Googleシートへの記録やGoogle同期は**未接続**。
  既存の公開側 `personal-record.html` とは自動集計しません。
- 保存先は同じブラウザーの `localStorage` のみで、サーバーへの送信はなし。
  ChatGPT内ブラウザーとSafariの保存領域が分かれる場合があります。
  プライベートブラウズ、閲覧データ削除、端末変更、再インストールでは
  記録が失われることがあるため、SafariからJSONバックアップを推奨。
  下書き・実戦購入記録はそれぞれ **JSONの書き出しと復元** に対応。復元は本人が選んだバックアップファイルをブラウザー内で解析し、種類・上限・重複・点数・購入額を検証したあと、確認ダイアログを経て **現在の同種記録を全件置き換える**。混ぜ合わせ・自動マージは行わない。復元前に必ず現在の記録をJSONでバックアップ。1ファイル上限1MB、下書き300件・購入500件まで。自動同期・サーバー保存は未対応。
- 最大300レースの手動下書き。既存レースを上書きする際と削除する際は
  操作確認。保存失敗時には成功表示をしません。
- 本人専用 Basic または署名Cookie認証と同一 HTTPS サービス内だけで
  HTML・JS・CSSを提供します。未認証アクセスはログイン画面へ案内し、
  有料データや予想履歴を含むレスポンスは返しません。
- Render の Free はスリープします。GitHub自動テスト成功後の
  デプロイ設定をユーザーが有効にしていますが、
  GitHub統合だけで実際の Render 配信済みとは断定できません。

- **「評価入力済」**は本人が保存した5項目すべてがS/A/B/Cの形式で埋まっていることを意味する。AIが能力を予測したことではない。**「3連単下書」**は有効なフォーメーションが端末に保存されていること、**「購入記録」**は本人が購入したと手動で入力した記録があること。実際にJRAで購入できたという証明ではない。
- Rをタップすると、現在の資料段階と「評価する」「3連単を作る」「馬番メモへ」を表示する。前2つには**日付・競馬場・Rだけ**をURLフラグメントで渡す。本人の馬名・有料メール・買い目・購入履歴をURLやRenderへ送らず、移動先も保存・購入は別操作。
- メールや馬番メモが届いた時点で自動インポートする機能はまだない。ブラウザー保存領域を変更すると記録が別になる場合がある。端末変更・容量不足に備え、`/owner-backup` でJSONバックアップを作成する。
- 安全対策：全資料の件数上限、ブラウザーの壊れたJSONの検出、馬番メモの元資料一致、3連単の48点上限（表示のみ）、本人認証、読み取り専用を `scripts/check-owner-race-workbench-ui.cjs` と `tests/test_private_service.py` でテスト。元データが壊れた場合はゼロ件や全件準備完了としてごまかさず、画面に読込エラーを表示する。

コードは `scripts/owner_race_workbench.py`、配信URLは `/owner-races`。**GitHubのテスト成功とRender本人用サービスへの最新版デプロイ成功をそれぞれ確認する**。GitHub Actionsが緑でも、Renderの旧版にはまだ機能が届かない。
