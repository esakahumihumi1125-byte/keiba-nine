# 競馬ナイン：評価と1着候補の研究基準 v1

目的は「総合評価が上位なのに、勝ち切れる馬を3着欄にしか置かない」
取りこぼしの再点検です。画面は単純に保ち、裏側の評価根拠を揃えます。

現段階は架空データ限定の未検証ルールです。実データへの適用、公開予想、
購入推奨、配信JSON、保存済みの予想には接続していません。

## 各項目の評価を作る際の基準

- S：今回の条件に強く合う具体的根拠が複数あり、重要な反証も検討済み。
- A：今回の条件に合う明確なプラス材料がある。
- B：評価できる資料はあるが、優位性は限定的・条件付き。
- C：今回の条件では具体的な不利材料がある。
- 未評価：情報不足、出所不明、または予想時点では未入手。

着順だけ、時計だけ、血統名だけで評価を決めません。Cは「情報なし」ではありません。
数値評価の境界は今後検証する仮説であり、Sは勝率や的中保証を表しません。

| 項目 | 確認する材料 | 仮の配分 |
|---|---|---:|
| 調教 | 最終・1週前、時計・ラップ、コース・負荷、併せ馬、前走比較、コメント | 20 |
| 近走 | 相手・クラス、着差、通過順、内容、不利、大敗の理由と改善 | 20 |
| コース・距離 | 同条件の内容、右左回り、坂、距離延長短縮 | 20 |
| 展開・脚質 | 逃げ先行の頭数、想定ペース、位置取り、勝ち筋 | 15 |
| 馬場 | 想定馬場と適性。良と重・不良の根拠を区別 | 10 |
| 血統 | 距離・芝ダート・馬場に関する補助材料 | 5 |
| 枠・斤量 | 枠の有利不利と実際の脚質、斤量変化 | 3 |
| 騎手・厩舎 | 条件との相性、乗替わり、準備状況 | 3 |
| ローテ | 間隔、休み明け、叩き回数、輸送 | 2 |
| 馬体・状態 | 入手できた馬体重、状態。未発表は未評価 | 2 |

同じ資料が複数項目の根拠になる場合は二重評価に注意します。
調教の一部しか取れない場合は、揃っていない項目を根拠文に明記します。
生のJRDBデータからこの項目別評価に変換する処理は、まだ未実装です。

## 計算と欠損の扱い

実装：`scripts/evaluation_policy.py` の `evaluate_race`。
評価済みの S/A/B/C を 3/2/1/0 とし、上記配分で合計します。
調教・近走・コース距離・展開・馬場の5項目がすべて揃い、確認済み配分が
85以上の場合だけ総合ランクを計算します。それ以外は「未評価」。
欠損分を残りの項目に再配分して、高評価にすることはしません。
仮の境界は S=2.6以上、A=2.0以上、B=1.0以上、C=それ未満です。
同点は同順位にし、馬番順は表示を安定させるためだけに使います。
新馬など近走のない馬は現ルールでは未評価。別の新馬用基準を検証するまでは
既走馬向けの基準で自動的に評価しません。

## 1着候補の再点検

1. 総合順位に関係なく、全馬の勝ち切る根拠を確認する。
2. 調教・近走・適性・展開のうち2項目以上でA以上、かつ根拠付きの
   `winSupport: true` がある馬を再検討候補にする。
3. 明確な懸念がある馬、確認できていない懸念がある馬は自動採用しない。
4. 4頭以上残った場合、上位3頭に機械的に切らず「要再検討」とする。
5. 1頭しか残っても、他馬の情報不足による見かけの優位を確認する。
   この版では1頭固定を自動決定しない。

出力は「再検討候補」で、最終1着候補や買い目ではありません。
購入判断は必ず保留、`first` は空、`status` は draft です。

## 入力の根拠・時刻

入力は `recordType: test`, `asOf`, `offAt`, `horses`。
各馬は `number`, `assessments`（表の各項目の英語キー）, `blockingConcerns`。
項目ごとに `grade`, `reason`, `evidence` が必要です。
根拠は `sourceId`, `reference`, `availableAt` で追跡します。
時刻はタイムゾーン付きISO形式。予想時点より後に取得した資料は使いません。
この時刻は入力値の整合性チェックであり、資料の真正性の証明ではありません。

的中着順や払戻を評価の入力に使わず、検証結果として別管理します。
オッズ・人気はこの評価器の入力項目にありません。

## 検証と次の工程

`python -m unittest discover -s tests -p 'test_evaluation_policy.py'`

欠損、未来の資料、同点、懸念、上位以外の候補、候補過多、実データの拒否を検証。
実データ取得後は時系列で開発期間と検証期間を分け、固定した基準を未使用期間で
評価します。回収率だけでなく全購入点数・レース数・最大連敗・損失も記録します。
検証が済むまで、配分や境界を精度向上が確認された数値として扱いません。
