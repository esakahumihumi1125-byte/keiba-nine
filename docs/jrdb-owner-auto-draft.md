# 競馬ナイン：本人用「全場・全Rの自動暫定予想」v1

更新：2026-11-08

## 本人用画面

本人専用Renderにログイン後、ホームの
「全場・全Rの自動暫定予想と3連単下書き」
または /owner-auto-forecast を開く。

1. 本人専用のページを開くと、当日分の自動分析を1回実行。
   日付を変える場合や再分析する場合は日付と「全場・全Rを再分析する」を使う
2. 私的なJRDB β版の番組(/tra)、出走馬(/tky)、
   調教(/tcy)、近走(/tze)を開催日単位で各1回取得
3. 正規化済みの馬番と2項目仮評価を使って、馬を仮評価順に並べる
4. 全頭の資料が揃い、得点の同点境界に問題がなく、
   JRDB記載の暫定発走時刻前のレースに限り3連単下書きを自動表示
5. 各競馬場・レースから1着/2着/3着の馬番、全買い目、
   点数、1点100円換算の仮額を確認できる
6. 発走前に作成できた研究用買い目をサーバー時刻で署名し、
   **同じiPhoneの端末内に自動保存**。既存の同日・同Rは上書きしない。
   署名付き記録は本人用100円仮想収支画面で読み取り可能。
   公式結果は未接続なので、買い目の結果は「保留」のまま。
   サーバー長期保存や実際の購入履歴には書き込まない

**これは研究用の機械的候補であり、勝率や正式予想ではない。**

## 研究用の仮評価

- 調教：追切指数・仕上指数に独自の未検証閾値
- 近走：着順と直近のIDMに独自の未検証閾値
- S（金）、A（赤）、B、Cは2項目だけの研究評価
- 同得点の馬は「仮順位」を共有。馬番を能力差として扱わない
- 全頭のいずれかに欠測があれば3連単案を生成せず見送り
- 1着は原則2頭。同点境界を切れない混戦だけ3頭も検討
- 2着・3着の候補は同点の馬を不当に分けないように調整
- 3連単は重複除外・最大40点。7頭で40点、
  6頭で32点、5頭で24点の例（全馬の2項目点数が異なる場合）
- 少頭数・資料不足・同点境界の不整合は無理に点数を増やさない
- 発走後にさかのぼって3連単下書きは作らない

## 安全ガードと未接続事項

- JRDB_PRIVATE_ENABLED=1、KEIBA_RENDER_PRIVATE_ONLY=1の
  本人専用サービスのみ、本人認証と同一オリジンヘッダー必須
- 一般プレビューは画面404、実データAPIは503で停止
- APIキーや認証キーが無ければ予想案を生成しない
- APIキー、元の有料指数・履歴・馬名・馬IDを画面に返さない
- JRDBの元資料や有料指数は保存しない。作成した研究用の馬番と
  サーバー署名付き買い目だけ本人端末に保存し、後から更新しない
- Safariとホーム画面版では保存領域が異なる場合がある。
  既存の本人用7種類バックアップに固定研究記録も含む
- 実際の購入や正式収支、既に固定済みの予想を変更しない
- JRA公式の最終出走馬・取消・馬場・発走時刻の独立確認は未接続
- 総合10項目評価、確定3連単、WIN5、自動投票とは別
- 実機Safari・本番JRDB β版応答の検証はまだ必要

## 土曜日の利用状況・次の操作（2026-11-09）

- 本人用画面の上部に、受信済みの同一日付の検証済み資料だけから「次の操作」を表示。追加JRDB問い合わせ・公式データ自動取得・馬券変更は行わない。
- 番組0件：**開催なしと断定せず**、日付・掲載タイミング・JRDB設定の確認を案内する。全R見送り：理由の大きい順に最大2種類を示し、既存の見送り理由ボタンへ誘導する。
- 研究用下書きあり：発走前の暫定下書き件数・見送り件数を表示して「下書きのみ」で候補の頭数・点数を確認するよう案内。ただし正式10項目100点、JRA公式出走・取消・馬場・発走時刻、購入可否は**未確認**と明記する。
- 既存の固定買い目との不一致・固定記録の読取エラーは優先警告とし、古い記録を消したり後から違う買い目を表示したりしない。401/403/429などの通信エラー時は取得失敗・新規予想なしを示し、既存固定記録の確認へ誘導する。
- 日付切替や通信中は旧日の件数を非表示にし、古い応答は再掲しない。本文の原データ、秘密トークン、オッズを表示しない。iPhone合成テストで検証する。

## 開催場別R数と固定記録の保全状況（2026-11-09）

- 本人用の当日自動予想の上部に、**取得できたJRDB番組の開催場・R数**を表示。各開催場の1〜12Rのうちデータにない番号を「未検出候補」として示す。これはJRA公式のレース一覧を自動取得した結果ではなく、**不開催・取消・レース削除を意味しない**。公式の全場・全Rとの独立した照合は未実施。
- 検証済みの同一日付のJRDB応答だけから表示し、重複番号や未知の開催場は安全に拒否する。東京・京都・福島の36R合成データ、1Rのみ、福島6Rだけ未検出の35R合成データで検証。再取得時の追加JRDB呼び出しはゼロ。
- 同じ画面で**このSafari/PWAの固定済み研究記録の件数**も表示。件数は端末の構造検査だけであり、HMAC署名の再検証、サーバー永続保存、実際の馬券購入や公式結果の確認を意味しない。記録が不正なら安全に照合を中止する。
- サーバー永続保存がOFFならその旨を明示し、Safariとホーム画面の保存領域が異なる可能性、`/owner-backup` での別保存を案内。新規署名固定の失敗時は「固定失敗」を表示して保存済みの元データを変更しない。
- 日付変更・通信エラー・日付またぎ再開時は古い取得内容を消す。JRA公式照合や正式10項目の採点、以前の3連単・固定履歴・100円仮想収支には変更を加えない。

## 正式な自動予想までの残作業

1. 本人専用Renderで当日のJRDB実接続と応答形式を確認
2. 残り8項目（コース距離、馬場、血統、ペース/展開、枠斤量、
   ローテ、騎手厩舎、馬体状態）の評価を実装・検証
3. JRA公式の確定出走馬・取消・馬場・時刻を独立照合
4. 過去データで順位、1着候補、3連単/3連複の回収率を検証
5. 発走前に確定版を自動保存して公式結果と突き合わせ、
   本人専用100円仮想収支へ反映
6. JRDB β版の利用規約・公開権利範囲を確認したうえで公開方針を判断

**現段階は「研究用の3連単案を自動作成」まで実装。**
「全レースの正式予想が毎日自動で完成」とはまだ言えない。

## 未評価の理由表示（2026-11-08）

本人用1R試算と自動暫定予想に、未評価の理由を馬番別に表示。
照合できる調教資料なし／調教指数不足、近走資料なし／使える過去走なし／
1走のみ／着順・指数がそろう資料が2走未満を区別する。
資料の不在を新馬やAPI故障と断定しない。指数や元の履歴は返さない。
既存の評価閾値、同点順位、保存済み買い目・購入記録は変更しない。
1R試算画面の上部から全R自動暫定予想へ直接移動できる。
