# ARC RACE: Windows用 JRA-VAN JV-Link 接続の確認

2026-11-18。本人用PCでJRA-VAN Data Lab. (JV-Link 64bit) の最初の接続を簡単に確認するための小さな**読取専用診断**。以前の Data Lab.検証ツールのセットアップに戻る必要はありません。

## PCを再開したときだけ

1. GitHub Desktopで最新の変更を取得したあと、リポジトリの `scripts/windows_check_jvlink.cmd` をダブルクリックする。
2. 黒いウィンドウに `JVLINK_CHECK=INIT_OK` と出たら、64bit COM作成と `JVInit("UNKNOWN")` の呼出しが成功した状態。
3. `COM_UNAVAILABLE`、`WRONG_BITNESS`、`INIT_FAILED` または `INIT_EXCEPTION` の場合はその**状態名だけ**共有する。アカウントの利用キー、パスワード、ダイアログの秘密情報を送らない。

**「INIT_OK」でもJRA公式出馬表の取得・払戻・取消・馬場・発走時刻の取得や利用権限が検証されたわけではありません。** 競馬予想への接続も未実装。

## 安全性

- 64bitのWindows PowerShellでローカルCOM `JVDTLab.JVLink` と `JVInit` の呼出しだけを確認。JVOpen/JVRTOpen/JVRead/JVGetsは実行しない。
- レースデータのダウンロード、追加課金対象のデータ取得、ネットワーク転送、秘密トークンの表示・保存、GitHub/Renderへの送信、馬券購入は行わない。JV-Linkの内部初期化通信の有無までは確認しない。
- `.cmd` のPowerShell実行ポリシー変更は**その起動プロセス限り**。Windows全体の設定は変えない。
- テストはLinux上の**静的検査のみ**。Windows実機でのCOM動作は未確認。SDK Ver.5.0.0 の64bit登録が想定。
- 現段階で本番アプリへの統合や自動同期はなし。JRA-VAN Data Lab.の個人利用・転載・ソフトウェア登録条件は正式利用前に別途確認する。

## JRA-VAN RA/SEの固定長出馬表候補を読む（2026-11-18、開発用）

`scripts/jvdata_ra_se_candidate.py` を追加。正式なJRA-VAN JV-Dataの「RA レース詳細（1272バイト）」と「SE 馬毎レース情報（555バイト）」の**出馬表データ区分2**を対象に、開催日・場・開催回・開催日目・レース番号・馬番とRAの予定発走時刻を、サーバーへ送らず**プライベートなメモリ内だけ**で検証します。独自のレコード順序や改行変換を推測せず、現行の固定長・末尾CRLFを要件とします。

JRDBの同日/場/Rの番組と馬番集合・頭数・予定時刻を比較する関数も用意しました。返すのは、馬番候補の一致などと**最終確認が未完了**という状態だけで、出走確定・取消なし・最新馬場・確定発走時刻を保証しません。馬名・血統登録番号・有料レコード本体は出力しません。過去成績データ区分3〜7を出馬表に混ぜません。

**現時点の境界**：`scripts/windows_check_jvlink.cmd` ではまだJVInitのみを試します。JVOpen、JVRead、RA/SE抽出は**未実装**で、PC上の実データ取得も試していません。これらのパーサーは合成レコードでのテストのみです。JV-Dataの利用権限も自動認証しません。取得時点とJV-Linkの元データが真正か、RA/SE以降の変更情報を取りこぼしていないかを別途検証するまでは正式10項目採点ゲートへ通しません。

技術資料： [JRA-VAN現行SDK](https://developer.jra-van.jp/t/topic/45)、[JV-Data仕様書](https://jra-van.jp/dlb/sdv/sdk/JV-Data4901.pdf)、[RAフィールドの読み方](https://ht-0328.github.io/jvdata-store/reference/RA/)、[SEフィールドの読み方](https://ht-0328.github.io/jvdata-store/reference/SE/)。

## 「今週データ」を本人PCで1回だけ取得する実行ファイル（2026-11-18）

- **まだ実機未検証。** 開発ブランチの `scripts/windows_jvlink_weekly_read.cmd` をダブルクリック。**Enterだけなら直近の土曜日**、日曜や祝日なら開催日を `YYYYMMDD` で1回入力する想定。PCのWindowsにJV-Link 64bitと、64bit Python（pywin32ライブラリ）がインストールされている必要がある。Pythonを自動インストールせず、権限のないAPIを自動連打しない。
- `windows_jvlink_weekly_read.py` は `JVInit("UNKNOWN")` → **1回だけ** `JVOpen("RACE","00000000000000",2,...)` → 最大5,000レコード（小さいWindows PCでのCOMバッファ消費を抑えるため）の `JVGets` → `JVClose`。公式JV-Data option 2（今週データ）のみで、過去データのsetup option 3/4、通常蓄積 option 1、リアルタイム監視は行わない。実行対象日はPC現地日付から7日以内の今日以降だけ。
- 取り出すのは対象開催日の**出馬表区分2のRA/SE**のみ。日付・競馬場・レース・馬番・登録頭数が完全一致した場合だけ、各場各Rの候補をまとめる。区分3以降の結果や馬名、血統ID、ファイル名、生レコードは保存しない。欠損や矛盾、取得上限超過、JVClose失敗なら全体を保留。
- 成功時には `%LOCALAPPDATA%\ARC-RACE-private\jvdata-candidate-YYYYMMDD.json` に**非公開の候補要約だけ**保存する。OneDriveとGitHubの作業フォルダを避けるため通常のDocumentsには保存しない。候補JSONを同じフォルダで完全に書いてから原子的に確定名へリンクし、途中書き込みで不完全な確定ファイルを残さない。同じ開催日のファイルが既に存在したら**上書きしない**。後の発走前記録と混同しないため、現在は追記や自動再取得を許可しない。JSONを公開リポジトリ、チャット、SNS、Google Driveに転送しない。
- 失敗時は `ARCRACE_WEEKLY_READ=...` の**固定ステータス名のみ**表示。完全なエラーログ、利用キーや実レース原票は送らない。 `PYWIN32_NOT_INSTALLED` なら同じ64bit Python環境にpywin32が未導入。 `JVOPEN_NOT_READY` はJV-Linkや利用状態、今週データの提供状態を公式設定で個別に確認する必要があるが、**自動で再試行しない**。
- 正常終了時に**取得できたレース数、観測できた競馬場数、その競馬場の各12Rがそろっているか**を表示。これはその日に開催される**すべての競馬場を観測できた証明ではない**。未確認の会場や提供開始前のレースがあり得るため、最新データ不足時は正式採点へ昇格しない。
- **重要**: これはJRA最終確定の証明ではなく、候補馬番・予定時刻だけ。AV(出走取消・除外)、WE(馬場)、TC(発走時刻変更)、WH(馬体重)の直前変更と元データの真正性・配信タイミング・出走馬最終確定はまだ未接続。本人用Renderへの取り込み、正式100点採点、全場全R3連単自動生成・公式結果照合は**未完成**。
- LinuxのGitHub Actionsでは合成COMを使ったテストのみ。実際のJRA-VANサーバーへの有料アクセス、Windows COM動作、利用キーの認証、配信の同時性、契約適合性は確認していない。

[公式Data Lab. SDK・JV-Linkドキュメント](https://developer.jra-van.jp/t/topic/45) を参照。


## 同日全RをJRDBと比較する内部処理（2026-11-18）

`scripts/owner_jvdata_jrdb_day_check.py` は**本人認証済みのサーバーか個人PC内の処理として利用する想定**。既存の `windows_jvlink_weekly_read.py` が作った候補結果と、JRDBですでに正規化した同日 `/tra` と `/tky`（当日場・R・頭数・馬番・予定発走時刻）をレース単位に照合し、候補一致・不足・不一致を診断する。新しいJRA-VAN取得や有料JRDB API通信は一切しない。馬名・有料原票・馬IDは結果に含めない。

- **候補が一致しても**出走取消・除外・馬場・当日発走時刻変更を最新速報で確認していないため、`finalJraStarterListVerified=false`、`formalTenFactorReady=false`、`bettingReady=false`。
- JRDB側にRがあるのにJRA-VAN候補がない場合は `missing_jvdata_candidate` とする。馬番集合・予定時刻・頭数が異なる場合は `hold_source_mismatch`。日付違い、異なる競馬場や別レースの混入・重複・不正な採点許可フラグは処理を拒否する。
- **現時点では関数と合成テストのみ**。Windowsでの実データ取得、Render本人用認証とのファイル連携、インターネット転送、公式最終確認との結合は行っていない。JRA-VANの契約・再利用/再配信条件に従う必要がある。

## ダウンロード中待機・PC内の見やすい一覧（2026-11-18 追加）

- JRA-VAN公式の `JVGets=-3` は**通信ダウンロード継続中**であり、従来のような即時エラーではありません。新しいプログラムは単一の`JVOpen`内で最大90秒、2秒ずつ有限の待機を行い、それでもダウンロードが続けば`JVDOWNLOAD_STILL_PENDING`で保留して`JVClose`。自動で再Openせず、失敗した途中結果は保存しません。合成テストで回復とタイムアウトの両方を確認。
- 一回の取得成功時は、レース候補JSONに加え**PC内限定の一覧HTML**も生成。東京・京都など競馬場別のR/発走予定時刻/候補頭数だけを表示し、馬名・血統ID・契約情報・元データを出しません。外部JavaScript・通信・画像リソースもありません。Windowsでは成功後にローカルHTMLを既定ブラウザーで開く予定。
- 保存先は`%LOCALAPPDATA%\\ARC-RACE-private\\jvdata-candidate-YYYYMMDD.html`。HTMLと候補JSONを同一フォルダに完全作成してから最終名で確定し、失敗時はその回の結果を採用しません。同一開催日のファイルは上書きしません。
- ブラウザーの表示はあくまで**出馬表候補の確認画面**。正式に最新のJRA出走・取消・馬場・発走時刻を確認できた状態ではありませんし、ARC RACEの本番本人用画面にもまだ同期していません。PC版JRA-VAN、64bit Python+pywin32の実機稼働も未検証です。

## 発走前データと発走後読み取りを区別する追加ゲート（2026-11-18）

- `windows_jvlink_weekly_read.py` はJV-Link読込後にPCローカル時計のJST時刻を `capturedAtLocalJst` として候補要約に記録し、各Rの**RA記載の発走予定時刻より前に取得されたか**を `beforeScheduledOffAtLocalCapture` に記録する。既に予定発走時刻後ならPCのローカル一覧に「発走予定時刻後の取得・予想使用禁止」と表示する。
- `owner_jvdata_jrdb_day_check.py` は同じ時刻から発走前／発走後フラグを**再計算**してから突合。発走後レースを `post_off_local_capture` として保留し、馬番が一致しても候補合格にしない。収集時刻やフラグの矛盾したローカルファイルは全体を拒否する。
- **重要な限界**：PCの時計は独立認証されておらず、JV-Link原本の初回公開時刻も確認していない。RAの予定発走時刻は直前変更が未反映の場合もある。したがって、発走前のローカル時刻に読み込んだからといって「公式確定の発走前資料」「予想作成済み」「当日最終照合済み」の証明にはならない。独立したJRA速報・本番保存・配信条件は未実装。

## 初回の「馬番付きデータなし」を区別する診断（2026-11-18）

11月18日の本人ThinkPadでは64bit Python・pywin32・JVInitが成功した後、11月21日開催日の初回読取が `NO_NUMBERED_CARDS_FOR_DAY` で終了。この旧コードだけでは、**取得対象のデータがまだ現れない**ことと**他の日付・別区分のレコードしか見えない**ことを区別できなかった。無料体験契約の成否やJRAの配信開始は、この結果だけでは分からない。

同じ**1回だけのJVOpen**で、取得失敗時の固定状態コードを追加した（数や生データは表示しない）。

- `NO_WEEKLY_PAYLOAD_RECORDS`：JVOpen成功、読取でレコード本体を1件も観測しなかった
- `NO_NUMBERED_RA_SE_RECORDS`：レコードは観測したが、RA/SEの出馬表データ区分2を1件も観測しなかった
- `NO_TARGET_DAY_NUMBERED_RA_SE`：区分2のRA/SEは観測したが、指定開催日のものがなかった
- `NO_NUMBERED_CARDS_FOR_DAY`：上記以外でも安全な馬番付き出馬表を完成できなかった場合の従来の保留コード

`ARCRACE_NEXT_STEP` に表示する説明はプログラム固定の一般的な文だけ。**「発表前」「契約不備」などの原因を推測で断定しない**。引き続き自動再試行、実データのアップロード、正式予想への採用はしない。新コードは開発用PR内で、PCへ配布するZIPは新しいGitHub Actionsの合成テストと成果物作成の成功後にのみ更新される。現時点の旧ZIPを上書きする処理はない。

## 過去5走の着順・時計・位置取りを研究用に整理（2026-11-19）

`scripts/owner_jvdata_horse_history_preview.py`を開発版に追加。公式JV-Data Ver.4.9.0.1の固定長`SE7`（555バイト）から、**既にライセンスのあるローカル原票だけ**を対象に、直近5走の`確定着順`、`走破時計`、1〜4コーナー通過順位、`後3Fタイム`、過去レースの脚質判定コードを各馬番へ集約する。人気・オッズをスコア用に読み込まない。参考：公式レコード仕様書と項目位置の解説（https://ht-0328.github.io/jvdata-store/reference/SE/）。

- 登録IDを一時的に内部照合し、当日出走馬候補の馬番へ結びつける。過去の馬番では結合しない。生原票・血統登録IDは結果に含めない
- 過去の施行日とSEのデータ作成日が対象開催日以後／ローカル採取日より未来なら保留。データ更新日の**日付だけ**が分かっても当日何時に提供されたかは保証できず、`dataAvailabilityIndependentlyVerified=false`のまま
- 各馬の直近5走のみで、欠測・0・特別な999系の値を好成績として扱わない。過去走が0件でも新馬戦／デビュー馬と断定しない。矛盾する同一過去レースの再送は拒否
- SEにレースの距離・コース馬場がないため、`distanceMeters`、`surface`、`going`は**不明（null）**。距離・馬場適性を採点するには歴史的RAとの正確な同一開催照合が別途必要
- 当日発走時刻を過ぎて取得された候補からは過去走を表示せず、過去の予想を遡及的に生成しない
- `formalTenFactorReady`、`predictionReady`、`bettingReady`はすべてfalse。**現在は研究用であり、100点採点もiPhone本番反映も行わない**
- 新しいテストは合成`SE7`だけを使用。今週のPC確認ZIPにこの履歴解釈機能が自動搭載されるわけではなく、実`RCVN`の取得・履歴データ補てんは今後別途実装する


## 過去レースのRA7をSE7に厳密結合（2026-11-19）

`owner_jvdata_horse_history_preview.py` は任意の`historical_ra`として、あらかじめ本人PC内で取得済みの歴史的なRA7を受け付ける。JRA-VAN公式のRA仕様書にあるレースの**開催年・月日・場・開催回・開催日目・R番号の6つすべて**が、各SE7結果と一致した場合にのみ、当時の`distanceMeters`（位置698〜701）、`historicalTrackCode`（706〜707）、芝馬場（889）、ダート馬場（890）のフィールドを付与する。参照: https://ht-0328.github.io/jvdata-store/reference/RA/ と https://targetfaq.jra-van.jp/faq/detail?id=707&site=SVKNEGBV 。

- 距離・馬場があるだけで**距離適性や良馬場適性の点数は付けない**。公式コード表にないトラック、障害で芝/ダート混在、未設定（0）は不明のまま
- 当日の同一開催とは関係のない過去RA、過去SEと開催回・日目が食い違うRAは結合しない
- データ作成日がローカル撮影日より未来の歴史的RA7や、同一レースに異なる内容のRAが混入した場合は拒否。同一内容の再送は重複として処理
- **現在は合成データだけでのテスト**。正式10項目のコース距離点・展開点・馬場点を生成せず、JRA-VANから実`RCVN`をダウンロードしたわけでもない。個人用PC・非公開アプリに必要なデータ権限確認も残る


## 馬の過去走補てんデータRCVN：PC実データ有無を1回だけ検査（2026-11-19）

本人用PCの実機で、出馬表候補`RACE`だけでなく、JRA-VANが提供する**過去の馬データ補てん`RCVN`**が使えるかを確かめるため、別の確認用`scripts/windows_jvlink_horse_data_probe.cmd`を追加した。JRA-VANスタッフは古い`RCOV`の代わりに`RCVN`を試すよう案内している（2026-11-05）：https://developer.jra-van.jp/t/topic/1340

## 2026-11-21：RCVNの「照合0件」の理由を識別する安全な件数表示

実機の `DAY_HISTORY_NO_MATCHED_RCVN_HORSE_ROWS` は、候補馬に一致する過去SE7が見つからなかった意味であり、契約・配信・過去走の全不存在は証明しない。
同日中に再試行を繰り返す必要はない。今回すでに終了したRCVNの原レコードは保存していないため、**過去の失敗ログから後付けで件数を復元することもできない**。

今後、ユーザーが明示的に実行を許可した一度の読取が正常終了した際だけ、黒い画面に以下の**件数だけ**を表示する（馬番・登録番号・馬名・生レコード・認証情報を表示、保存、送信しない）。

- `CANDIDATE_FLAT_RACES`：発走予定前で完全な平地候補レースの数
- `CANDIDATE_HORSES`：同候補に所属する一意な馬の登録ID件数（ID自体は表示しない）
- `RCVN_RA7_ROWS_OBSERVED`：RCVNで実際に読めた過去RA7レコード数
- `RCVN_SE7_ROWS_OBSERVED`：RCVNで実際に読めた過去SE7レコード数
- `RCVN_MATCHED_SE7_ROWS`：今回の対象馬IDと一致したSE7レコード数

例えばSE7が0なら配信されたストリームで過去SE7を観測できなかったこと、SE7はあるのに一致0なら**この読取範囲での照合0**と区別できる。どちらも過去走の網羅性、配信時刻、JRAの最終出走馬、正式10項目採点の根拠にはならない。部分的な記録や件数上限で終了した場合、完成した全履歴として扱わない。RACEとRCVNの追加照会回数は増やさない。
