# JRDB「想定確定」メールの本人専用・端末内取り込み

- URL: ログイン済み本人用 `/jrdb-mail-local`。本人がGmail等から**1通または複数通のメール本文を貼り付ける**方式で、Gmail自動同期はまだありません。
- `■想定確定`、開催日・競馬場・発走予定時刻、1R〜12R、予定登録頭数と馬名の並びを解析し、`localStorage` に**開催日・競馬場・レース・時刻・予定頭数・馬名のみ**保存。メール原文、騎手名、厩舎名、提供元の権利表示などは保存しません。
- 取り込み成功後、メール本文の入力欄は自動クリア。同じ日付・競馬場は変更点を確認してから置き換え、別会場は保持。保存件数は最大48開催組み合わせ。
- メール本文が不完全で、予定頭数と抽出できた馬名数が一致しない場合は**保存しない**。重複レース、馬名重複、不正な開催日時、19頭以上、不正形式も拒否。
- HTML/JS/CSSコードだけを既存の本人認証付きRenderから配信します。メール本文と解析した実データを**サーバーへPOST/送信しません**。GitHub・公開Pages・Googleスプレッドシート・ChatGPTへの自動転送もしません。
- 既存の3連単下書きや実購入のブラウザー保存領域とは**別キー**を使用し、消去ボタンでも今回取り込んだ想定メール予定しか消去しません。
- 本人用の競馬予想に限ります。JRDBの一般公開・再配布禁止条項を遵守。サブスク・一般公開向けフィードとは絶対に接続しません。
- **馬番・枠順が未確定の「想定確定」メールから3連単は作成しない**。JRAの公式出馬表・取消・騎手・斤量・馬場・発走時刻は後で独立して最終照合します。適性・調教ランクや予想は別工程。
- メール文面の構造が変わった場合は無理に取り込まず、明確なエラーを表示します。解析の正確性は実メール全種について未検証です。

公式規約：https://jrdb.com/terms

実装・テスト：`scripts/jrdb_mail_local_import.py`、`tests/test_jrdb_mail_local_import.py`、`scripts/check-private-jrdb-mail-local.cjs`。

## 2026-11-05：翌日以降の更新メールと複数通の取込

- `■想定確定` メールを**1〜12通まとめて貼り付け**できる。全体最大192,000文字、各通最大64,000文字。Gmailから直接取得する機能ではなく、本人がメール本文をコピーして結合する必要があります。
- **一括検証を完了してから、端末に一度だけ保存**。1通でも不正・途中欠落・頭数不一致がある場合は、取り込みを丸ごと中止し、保存済みデータは一切変更しません。
- 前回と同一の開催日・競馬場を再度受け取った場合、レースの新規追加、想定馬名・発走予定時刻・登録頭数の変更を比較し、本人の確認後に更新。何も変わらない場合は保存し直しません。
- 新しいメールに以前存在したRが欠けている場合は古い予定を保護して上書き拒否。メールが「枠確定」「変更」など**別の形式**なら、誤認して取り込まず、形式ごとに別途対応が必要です。
- 現在選択中の開催だけ削除する機能を追加。購入記録や手動3連単、他の開催日には影響を与えません。最大48開催を超える場合は、古い予定を勝手に消さず、明示的に整理が必要です。
- 新しい想定メールを読み込んでも馬番・取消・JRA公式確定情報が検証されたことにはなりません。馬名の掲載を実戦のS/A/B/Cや3連単に昇格しません。

## 2026-11-05：想定馬名と本人転記の確定馬番を照合

ログイン済み `/jrdb-mail-local` の**「JRAの確定馬番と想定馬名を照合（手入力）」**を実装しました。

1. すでに取り込んだ日付・競馬場を選び、1R〜12Rから対象Rを選択。
2. JRAの出馬表を確認し、自分で馬番と馬名を1行ずつ貼ります。例：`1 テストホースA`、`② テストホースB`。数値・丸数字の馬番1〜18に対応。馬番重複、馬名重複、構文不正、19頭以上は拒否。
3. **「想定馬名と照合する」**で、同じ馬名、想定メールにのみ掲載、馬番付きのリストにのみ掲載、を**件数と馬名で区別して表示**。比較だけなら保存しません。
4. 本人が差分を確認した後、明示的に**「確認した馬番の対応を端末に保存」**で保存。差異がある場合も、取消や追加と自動断定せず、必ず保存確認を出します。レース選択が途中で変更されたら再照合が必要。
5. 保存対象はブラウザーの別キー `keiba-nine-owner-manual-numbers-v1`。日付・競馬場・R・馬番と馬名の本人転記・照合対象となった想定メールのスナップショット文字列のみを保存。**Render / GitHub / ChatGPTへ送信しません**。下書き・実購入記録には一切加算しません。
6. 想定メールが更新されると、そのレースの手入力馬番対応は**「再照合が必要」**と表示します。以前の馬番メモを勝手に変更・削除・使用しません。レース単位で本人が削除できます。
7. **「このレースの3連単下書きへ進む（手動）」**では日付・競馬場・RだけをURLフラグメントで引き継ぎ、馬名・馬番・買い目を渡しません。遷移後も新しい買い目は自動作成・保存・購入されません。

**重要：** この仕組みは「本人がコピーした馬番と想定メールの馬名を比較」するだけで、JRA公式サイトの画面が正しいか、取消・枠順・馬場・発走時刻が最新かを自動保証しません。正式なJRA独立照合やJRDB実データ連携は未実装。事前想定から「公式照合済み」や「実戦予想可能」へ自動昇格させません。

実装：`scripts/jrdb_final_numbers_manual.py` / `scripts/owner_ticket_handoff.py`。テスト：`tests/test_jrdb_manual_numbers.py`、`scripts/check-private-jrdb-manual-numbers.cjs`、`scripts/check-owner-ticket-handoff.cjs`。

## JRA開催場別出馬表PDFリンクの本人用確認（2026-11-05）

本人専用画面 `/jrdb-mail-local` に、**「選択日の公式出馬表PDFを探す」**ボタンを設けた。

- 本人がボタンを押すと、既存の認証付き `GET /api/jra/official-pdf-links?date=YYYY-MM-DD` により、**JRA公式の固定URL `https://www.jra.go.jp/keiba/rpdf/` のHTMLページを1回だけ取得**し、指定日の「◯回 ◯◯競馬場◯日」の公式PDFリンクを探す。
- Python標準ライブラリのHTMLParserで公開索引の見出し・出馬表PDFへのリンクだけを読み取り、PDFファイルの内容は取得しない。日付はJST基準で過去56日から先14日までに制限。通信7秒・HTML最大900KB、公式URLドメイン/HTTPS/配下パスのみ許可、サーバー応答に馬番・生データを含めない。公式サイト側のHTML仕様変更・リンク未掲載・通信失敗なら未確認として扱う。
- レース馬番、枠順、取消、騎手、馬場、公式発走時刻は取得・検証していないので、`officialRunnerNumbersVerified=false`、`predictionReady=false`、`bettingReady=false` を必須にしている。リンク発見だけでは実戦予想を開放しない。
- クライアントでは日付変更後の古い検索結果を破棄し、公式JRAのPDFリンク以外は表示を拒否。PDFを本人が開いて確認後、下部の手入力馬番照合と接続できる。
- **注意：これは「公式出馬表の公開URLを探す」初期段階であり、「公式出馬表を自動解析して各馬番を取得する」実装ではない。** 公式ページのライブ構造・アクセス可否はテスト用HTMLでは検証できない。実サイトの未掲載/仕様変更ではリンクを表示しない可能性がある。
- APIキー/JRDB料金は不要。JRAページへの要求はボタン操作時だけで、定期巡回・大量スクレイピングはしない。ホーム画面の架空予想や実購入記録には影響しない。

参照：JRA公式「開催場別出馬表」 `https://www.jra.go.jp/keiba/rpdf/`。コード：`scripts/jra_official_pdf_discovery.py`、`scripts/jra_official_pdf_ui.py`、テスト：`tests/test_jra_official_pdf_discovery.py`、`scripts/check-private-jra-official-pdf-ui.cjs`。
