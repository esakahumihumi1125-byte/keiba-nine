# 競馬ナイン本人用：100円仮想収支・固定予想の検証

更新: 2026-11-08。/owner-100yen-review は本人専用の私的研究画面。
一般プレビューでは404、本人認証済みで同一オリジンの専用ヘッダーを伴う
APIだけが集計を返す。JRDB原資料・秘密キー・馬名・取引履歴を公開しない。

## 現在できること

- 開催日を選び、非公開の固定予想プレビューから1点100円の仮想収支を読む
- レース別・競馬場別の3連単・3連複の点数、保留数、的中数、
  仮想払戻・回収率を確認するための画面と計算処理
- 発走前 lockedAt が scheduledOffAt より早いという入力チェック
- 3連単の着順を厳密に照合、3連複は順不同、重複買い目を除去
- 公式結果を未確認のレースは保留し、確定投資額・回収率に入れない
- 実際の馬券購入・払戻・正式収支・実購入データには一切反映しない
- 認証、入力検証、情報非公開とUI構文をCIでテストする

## 現時点でできないこと

- JRA公式結果と払戻の自動・独立照合は未接続
- レース前スナップショットの改ざん不能な保存・時刻監査は未接続
- プレビューのlockedAt時刻が本当にレース前に生成されたかは、
  この読み取り専用アダプターだけでは独立に証明できない
- 予想と買い目の全レース自動生成は未完成
- APIは必ず results=[] で計算するため、現状は確定的中・
  確定払戻・回収率を捏造しない
- Renderの実環境に固定予想プレビューの非公開JSONがなければ、
  画面は「未登録」と表示する（故障やハズレ扱いではない）

## 将来の連携契約（機密情報はコミットしない）

本人専用Renderの KEIBA_OWNER_FROZEN_PREDICTIONS_JSON に限り、
以下の架空形状を受け付ける。実馬のデータ、秘密情報、有料原資料は
GitHub、チャットや公開画面へ送らない。

これは将来の読み取りプレビューであり、環境変数の手動編集に
改ざん耐性があると主張しない。公式の買い目・購入履歴・証明書ではない。

## 2026-11-08追加：サーバー署名付きの発走前研究記録

本人専用の前日暫定予想画面に「買い候補を発走前記録に固定」ボタンを追加。
本人が押すと /api/owner-freeze-preday は **サーバー内の配信済み予想だけ**
から買い候補の3連単を組み立て、発行時刻と署名を付ける。
ボタンから任意の馬番や過去時刻を送って署名する機能はない。

発行時刻がサーバー予想に記載された発走予定時刻以降なら発行しない。
既存の固定記録は同じレースの新しい記録で上書きしない。
これはサーバー発行時刻と買い目の改ざん検知であり、
**予定時刻はまだJRA公式の独立確認を通っていない**。
発走前予想の客観的な完全監査や最終出走馬照合ではない。

署名付き記録は本人の端末内だけに保存され、Renderに履歴保存はしない。
100円仮想収支画面が /api/owner-100yen-verify-receipts で署名を検証して、
公式結果が未確認なら全件を保留する。勝ち・負けは捏造しない。
所有者パスワードが変更された場合、従来の署名付き記録の
検証に失敗するため、キーのローテーションと記録の継続には
次段階で別の長期保管用署名キーと監査サービスが必要。

iPhoneのブラウザー保存領域の消失対策として、
本人用バックアップを **v4・全7種類**に更新。
7種類目は署名付き買い目。v1（4種類）・v2（5種類）・
v3（6種類）のバックアップを復元する場合、
存在しない新しい種類を勝手に消さない。
署名の真正性は復元後に本人専用サーバーで照合する。

## 2026-11-08追加：本番DB接続前の長期保存準備（未有効）

本人専用Postgres向けの**任意接続アダプター**と初期テーブル定義を追加。
保存キーは「開催日・競馬場・R」で一意。同じレースを再固定しても
**最初の署名付き記録を優先**し、上書き・削除しない。
追加時はPostgresの時計と暫定発走予定時刻を再比較する。
予想の評価順や買い目そのものは保存後に変更しない。

設定フラグは初期状態で **OFF**：
- KEIBA_OWNER_RECEIPT_ARCHIVE_ENABLED=1（本人専用に限る）
- KEIBA_OWNER_RECEIPT_ARCHIVE_DATABASE_URL（非公開のTLS Postgres接続URI）
- KEIBA_OWNER_RECEIPT_SIGNING_SECRET（ログインパスワードとは独立した、
  長期維持する48文字以上の十分に複雑な秘密値）
以上の秘密値は**GitHub・チャットに絶対貼らない**。

必要な本人専用のみの依存関係：
deploy/render-owner-private-requirements.txt
公開プレビュー側は引き続き
deploy/render-requirements.txt（gunicornだけ）を使う。
DB接続をONにする前に、本人用Renderサービスのbuild commandと
非公開DBが合致していることを確認する必要がある。

テーブル定義：migrations/owner_receipt_archive.sql
管理者が本人専用DBで適用する。アプリ権限はSELECT/INSERTだけに絞り、
UPDATE/DELETE/TRUNCATE/DDLを許可しない。バックアップ・リストア
の検証とDB料金の確認後にのみ有効化する。

**現段階ではDBの作成・接続・マイグレーション・課金は未実施。**
Renderのワークスペース選択とプラン確認が必要。
アプリはフラグOFFなら従来どおり端末内保存だけで動き、
DBが無いのに「サーバー保存成功」と報告しない。
ONでDBが失敗した場合は503で処理を停止し、端末に保存済みと誤認させない。
私的研究用であり、JRAの実際の発走時刻や結果の照合ではない。

今後、データを長期保存する場合はログインパスワードと署名キーを
別々に管理する。署名キーが失われた場合は過去記録の署名確認が
できなくなるため、秘密値の安全なバックアップ方針が必要。

## 自動運用への残作業

1. 発走前にだけ記録を作成する本人認証済み保存サービスと、
   レースID・タイムスタンプ・保存履歴の独立監査
2. JRA公式の出走取消・確定着順・100円払戻を、
   許諾とデータ真正性を確認した独立経路で安全に取得
3. 予想スナップショット・確定結果の同一レース照合、
   同着・返還・取消等の公式払戻例外処理
4. 過去の正式予想を後付けせず、正しい保留・中止・的中・払戻を
   回収率計算に反映する実接続テスト
5. 調教・近走の暫定2項目から全10項目への根拠付き評価、
   3連単フォーメーション自動生成と本人用への掲載
