# 競馬ナイン｜本人用・実データ1R自動試算パイロット

2026-11-06。目的は実レースの自動予想に向けた **最小1レースの取得→照合→暫定比較** を先に動かすこと。完全な予想や馬券作成が完成したわけではない。

## 配信画面

- 本人用ログイン後：`/owner-auto-trial`。ホーム、36R一覧の各レースから移動できる。
- 日付・競馬場・Rを選び、本人がボタンを押した時だけ `GET /api/jrdb/one-race-trial?date=YYYYMMDD&track=東京&race=1` を呼ぶ。画面を開いただけではJRDB通信しない。
- API未設定なら試算ボタンは無効。**架空馬や前回の予想で穴埋めしない**。
- Renderの認証済みの本人専用画面だけで利用可能。新たな公開予想・保存キー・Googleシート・自動購入・GitHub ActionsによるJRDB通信はない。

## 計算内容

既存の本人専用JRDBクライアントで `/tra`（番組）、`/tky`（馬）、`/tcy`（調教）、`/tze`（近走）の4データを日付指定で各1回取得し、同じ元データ日付・レースキー・馬番／馬IDを検査。選択した1Rの結果だけ返す。

- 調教は既存 `jrdb_training_hypothesis.py` が計算する暫定S/A/B/C（追切指数・仕上指数の低い方で独自閾値）。
- 近走は既存 `jrdb_recent_hypothesis.py` の暫定S/A/B/C（成績IDMと着順がそろった過去2走以上で独自閾値）。
- **両方そろった馬だけ** S=4/A=3/B=2/C=1の合計2〜8を計算し、暫定比較順に表示。同点は同順位、資料不足馬は順位なし。人気・オッズ、馬名、馬ID、生の有料指標は返さない。
- 公式JRA出馬表・取消・馬場の独立検証と、コース適性・血統・展開・枠斤量・ローテ・馬体の評価は **未完了**。したがって `predictionReady=false`、`overallRankReady=false`、`bettingReady=false`、`autoTicketReady=false` を固定。総合S/A/B/Cや3連単フォーメーションは生成しない。
- データ不足・複数の矛盾・同一馬の重複・開催日不一致などはエラー。存在しない数値・結果・馬番を補わない。

## 利用開始に必要な設定

1. JRDBから、**既存会員ログインとは別に** β版APIの専用テストアカウントとキーの案内を受ける。
2. 本人のみがアクセスできるRenderの `Environment` に、`JRDB_PRIVATE_ENABLED=1`、`JRDB_API_KEY`、`JRDB_AUTH_KEY` を設定する。キーやメール記載のパスワードは**チャット・GitHub・ドキュメントに貼らない**。
3. Renderが最新版をLiveとして配信し、本人用 `/owner-auto-trial` を開く。API接続の成立はこの1Rボタンで初めて検証される。接続設定あり表示だけでは通信成功を意味しない。
4. 研究用の順位が表示されても、まだ実馬の総合予想・購入可能な買い目には移らない。実戦予想へ進む前に独立JRA確定照合と残りの評価・予測モデル検証を実装する。

JRDBサポートからは非公開の本人専用アプリにおける自動取得・AI分析は許可されているが、同データ・二次分析の第三者公開は通常会員契約では許可されていない。一般公開や有料公開は別途契約が必要。

## テスト

`tests/test_jrdb_one_race_trial.py` は架空のJRDB形式データを使い、2項目の照合、欠損・なりすまし・重複の拒否、人気非使用、認証、禁止期間、単一Rのレスポンスを検査。`scripts/check-owner-auto-trial-ui.cjs` はiPhone風画面の明示クリック、ステータス未接続、参照URLだけの引き継ぎ、返答の安全性、端末内不保存を検査。全テストは本物のJRDB APIに接続しない。

## 2026-11-06：全Rの10項目「資料あり頭数」を自動集計

`scripts/jrdb_day_trial.py` の `owner-day-two-factor-trial-2` は、従来と同じ **4つの提供元データ（番組・馬・調教・近走）をそれぞれ1回だけ**取得して、既存の内部10項目素材マトリクスを併用する。外部へのAPI呼び出し・保存・自動購入は増えない。日付・レース・馬番／馬IDの厳格な照合を行い、不整合時は一括試算を停止する。

各Rの `factorCoverage.materialCountByFactor` は以下の**資料有無の頭数**であり、馬の強さや順位ではない。

| 項目 | 計上するもの | 未実装の実力評価 |
| --- | --- | --- |
| 調教 | 暫定の独自S/A/B/Cを算出できた馬 | 調教の総合妥当性・相手比較・当日調子 |
| 近走 | 暫定の独自S/A/B/Cを算出できた馬 | 着差・相手関係・クラス差・レベル |
| 展開・脚質 | 過去3走の4角通過位置が2走以上ある馬 | 今回の展開予想・脚質優劣 |
| 血統 | 父・母父の名前がある馬 | 距離・コース・馬場適性 |
| 枠・斤量 | 枠番号と負担重量の記録がある馬 | 枠有利・不利、斤量の影響 |
| ローテ | 直近の出走日が分かる馬 | 休養明け・詰めた間隔の良否 |
| 騎手・厩舎 | 騎手・調教師名の記録がある馬 | 騎手・厩舎の実績・有利不利 |
| 馬体 | 馬体形状関連コードの記録がある馬 | 当日の馬体重・気配・良否 |
| コース・距離 | **未チェック**（0頭） | 同条件の適性 |
| 馬場 | **未チェック**（0頭） | 当日の馬場状態・適性 |

サーバー内の `build_private_factor_matrix` → `enrich_entry_materials_matrix` → `enrich_personnel_body_matrix` で記録の存在を照合するが、元データの父名・血統原文・騎手名・指標などは返さない。ブラウザーには各項目の**集計頭数だけ**を返す。暫定の2項目比較順位以外の馬別能力・複数要素の合成得点は公開しない。

iPhoneの各Rを展開すると「10項目の資料記録」から各項目の `n/登録頭数` を読める。クライアントは10項目の完全性、頭数、2項目の値との整合、未チェック2項目が0であることを受信前に検証。データが壊れていれば全R表示を中止する。

**注意：** この進歩は「分析のためのデータの準備」であり、まだ **AIの全レース予想・自動ランク・3連単30〜40点作成ではない**。今後JRDBのβ版専用APIキー・JRA公式の独立した出走確定情報と取消確認・血統／適性／展開の実力評価が必要。

テスト：`tests/test_jrdb_day_trial.py` の源データ有無と非公開性、`scripts/check-owner-day-trial-ui.cjs` の10項目集計形式・未評価の不正な昇格拒否。ライブ提供元への通信なし。

## 2026-11-06：公開JRDB仕様の差異に対応した直線コース判定

JRDB公式β版ドキュメントで**同じ `/tra` の `turn_cd` に不一致**がある。`/docs/fields` は **`3=直線`**、`/docs/endpoints/today/tra` は **`9=直線`** と説明している。実際のβ版アカウントの返信データでどちらが届くかまだ確認できないため、現在は**両方を直線として受け入れる**（右1・左2は共通）。確認済みでないコードは引き続き「不明」とする。

合成の新潟芝1000mデータで3と9の両パターンを検査し、番組→コース・馬場照合への値渡しを確認した。**馬の直線適性をAI採点したわけではない**ため、予想・購入のブロックは維持する。β版の実データを取得できたら実応答を確認して最終確定する。
