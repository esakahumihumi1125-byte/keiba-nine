# 競馬ナイン：買い目と時系列検証の準備

この段階は架空データ専用です。研究用の `simulate` は購入推奨ではありません。
実データ・JRDB接続・ブラウザーの公開予想への接続はまだ有効にしていません。
料金の発生するAPI呼び出し、データの自動保存、外部送信もありません。

## 処理の流れ

1. `evaluation_policy.evaluate_race`：10項目の根拠と予想時点を確認。
2. `research_planner.plan_race`：勝ち切る候補、相手、最大40点を組み立て。
3. `research_backtest.backtest`：固定した予想を、別入力の結果と照合。

全段階が `recordType: test` 限定です。出力は draft / validated=false /
publishable=false。結果の数字が良くても、このフラグは自動変更されません。

## 見送り・保留・検証対象

| 状態 | 研究処理 |
|---|---|
| 重要な評価が未取得・懸念が未確認 | 保留 |
| 勝ち切る根拠のある候補が0頭 | 見送り |
| 候補が4頭以上 | 保留・全候補を再検討 |
| 候補が1頭だが十分な優位がない | 保留 |
| 1〜3頭の候補と相手が揃う | 架空検証用の買い目を生成 |

1頭固定は、総合S・3項目以上の勝ち切る根拠・次点とのスコア差0.5以上を
仮条件にしています。これは検証前の仮説であり、強い軸を保証する数値ではありません。

## 点数配分

- 1着：評価処理で再検討対象になった1〜3頭をすべて残す。
- 2着：総合S/A、または勝ち切る根拠で選ばれた候補。
- 3着：総合S/A/B、または勝ち切る根拠で選ばれた候補。
- 根拠付きの重大な懸念がある馬は、相手にも自動採用しない。
- 1頭の馬が同じ買い目の複数着順に重複する組み合わせは除く。
- 合計40点まで。1着候補ごとに上限を均等配分する。
- 相手候補は仮の優先度「2着スコア×2＋3着スコア」で整理する。
- 上限の境界で同評価になった組み合わせは、馬番順で恣意的に切らない。
  同評価のまとまりをすべて入れられない場合、そのまとまり以下を採用しない。
- 1着候補のどれかが0点になるなら、勝手に軸を減らさずレース全体を保留。
- 30点に届かなくても弱い候補を足さない。1点100円で計算する。

この配分は確率・期待値の最適化ではありません。実データで検証してから見直します。

## 時系列での検証

`backtest(races, outcomes, split_at)` は予想の入力と結果を別に受け取ります。
レースごとの評価・買い目を先に作り、ハッシュを残してから結果を参照します。
結果を差し替えても予想や買い目が変わらないことをテストしています。

`split_at` より前を development、以後を validation として別集計します。
予想作成から発走までが境界をまたぐ場合は拒否。境界は開催間に設定してください。
この処理は学習や自動最適化を行いません。人が検証期間を見てルールを修正した場合、
その期間は未使用検証期間ではなくなるため、新たな期間で確かめる必要があります。

集計するもの：

- 対象レース数、保留・見送り数、購入想定レース数、結果確定数
- 全買い目の購入想定額、払戻、収支、回収率
- 結果待ちの購入想定額、中止で返還された購入想定額
- 最大連続赤字レース数、累積収支のピークからの最大下落額

結果待ちは赤字として数えません。中止は全額返還として別記し、的中率・回収率の
母数から除外します。同着・出走取消の個別返還には未対応のため、明示的に拒否します。
複数の予想版を別レースとして二重計上しないよう、レースIDと開催日・場・Rの重複を拒否します。
同時刻のレースはレースID順で表示するため、最大下落額もその順の計算です。

```sh
python -m unittest discover -s tests -p 'test_*.py'
```

別途必要です。現時点で実際の予想精度や回収率が検証できたわけではありません。
