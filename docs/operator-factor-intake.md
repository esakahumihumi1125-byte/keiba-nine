# 競馬ナイン：本人が選ぶ1頭・1項目の資料入力チェック

## 目的

既存の Render 本人用プレビューに「本人用・評価資料の入力チェック」を追加しました。
現時点の JRDB API 契約・キー・利用許諾とは無関係に、iPhone で開催日、
競馬場、レース、馬番、10項目のうち1項目、資料の状態と種類を
**すべて選択肢から選び**、入力形式が正しいかだけ確認できます。

操作は1項目につき1回。自分が「資料を見た」と選んだ場合も、その出所、
内容の真正性、競走前に得られた情報であるか、精度は**検証していません**。

## 動作

- `POST /api/operator/factor-note` はログイン済みの本人用HTTPSだけで使用します。
  既存の Basic 認証・追加ヘッダー・同一サイト制限・`no-store` を維持します。
- `recordType: operator_factor_note` と、明示した **8つの列挙フィールド**のみ受理します。
  開催日、競馬場、レース1～12、馬番01～18、10要素の項目名、状態、
  本人が見た資料の種類を厳格に検証します。
- 勝ち馬、馬名、有料JRDBの個別データ、指数、成績、オッズ、
  馬券・払戻、自由記述、APIキー、画像、シークレットは送受信しません。
- サーバーは結果や本人のメモを**保存しません**。返信は入力欄の種類、
  本人の入力申告、サーバーの受信時刻と未評価フラグのみです。
  馬番もサーバー応答には出しません。
- 同一のページを開いている間だけ、現在の開催日・競馬場・R・馬番ごとに
  **入力済み項目数（最大10）**をブラウザー内メモリで表示します。
  同じ項目の再入力は上書きし、画面を再読み込みすると消えます。
- `gradedFactorCount=0`、`grade=未評価`、
  `jraOfficialFinalVerification=false`、
  `predictionReady=false`、`bettingReady=false` を固定。
  手入力をもってJRAの公式確認済みや、実馬の予想・買い目とはしません。

## 残る課題

これは自分用の画面操作と入力の妥当性チェックの足場です。
**データ自動取得、保存して翌日以降に再利用する記録、
実馬の能力S/A/B/C評価、3連単自動生成は未実装**です。

本人用 Render 環境のデプロイ更新も別工程です。
公開GitHub Pagesには有料データや本人の入力ログを移しません。
